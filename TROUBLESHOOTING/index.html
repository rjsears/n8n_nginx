    Quick Diagnostics¶

    Run these commands first to understand the current state:

    # Check all container status
docker compose ps

# Run health check
./scripts/health_check.sh

# View recent logs
docker compose logs --tail 50

# Check disk space
df -h

# Check memory
free -h

    Container Issues¶

    Container Won't Start¶

    Symptoms: Container shows "Exited" or keeps restarting

    Diagnosis: 

    # Check container logs
docker logs <container_name> --tail 100

# Check if container exists
docker compose ps -a

# Inspect container
docker inspect <container_name>

    Common Solutions:

    1. Port conflict: 

      # Find what's using the port
sudo netstat -tlpn | grep <port>
# or
sudo ss -tlpn | grep <port>

# Change port in .env and restart

    2. Volume permission issues: 

      # Check volume permissions
docker volume inspect <volume_name>

# Fix ownership (if needed)
docker exec <container> chown -R <user>:<group> /path

    3. Missing environment variables: 

      # Check .env file exists and has required vars
cat .env

# Regenerate if needed
./setup.sh

    Alpine Containers Stuck in "Created" State (LXC/AppArmor)¶

    Symptoms: Many alpine:latest containers accumulate in Created state and never run. Common when running Docker inside an LXC container (e.g., Proxmox).

    Diagnosis: 

    # List orphaned alpine containers
docker ps -a --filter "ancestor=alpine:latest"

# Inspect a stuck container for the AppArmor error
docker inspect <container_id> | grep -i error
# Look for: "apparmor" or "operation not permitted"

    Root Cause: The host's AppArmor profile blocks the alpine container from starting inside an unprivileged LXC. The container is created but cannot transition to running state.

    Solution: The Management Suite spawns short-lived alpine containers for system metrics collection and SSL renewal. As of the AppArmor fix, all such containers are launched with security_opt=["apparmor=unconfined"]. If you are running an older build, pull the latest image:

    docker compose pull n8n_management
docker compose up -d n8n_management

    Cleanup orphaned containers: 

    # Remove all stuck alpine containers (safe — they have no running processes)
docker ps -a --filter "ancestor=alpine:latest" --filter "status=created" -q | xargs -r docker rm -f
docker ps -a --filter "ancestor=alpine:latest" --filter "status=exited" -q | xargs -r docker rm -f

    Container Creation Fails: "docker-default profile could not be loaded" (LXC/AppArmor)¶

    Symptoms: Creating or recreating any container (docker compose up -d --force-recreate <service>, docker run ...) fails with:

    Error response from daemon: AppArmor enabled on system but the docker-default
profile could not be loaded: running '/usr/sbin/apparmor_parser -Kr ...' failed
with output: apparmor_parser: Unable to replace "docker-default".
apparmor_parser: Access denied. You need policy admin privileges to manage profiles.

    Already-running containers are unaffected — the error only appears when a container is created, which can make it look like it appeared "out of nowhere" months after install.

    Root Cause: The same underlying condition as the stuck-alpine issue above: Docker running inside an LXC guest (e.g., Proxmox) shares the host's kernel but is not allowed to load AppArmor policy into it. When the daemon creates a container with default confinement it must load its docker-default profile, and the load is denied. This affects every compose service, not just the management helpers.

    Solution: Every service needs apparmor:unconfined:

    services:
  <service>:
    security_opt:
      - apparmor:unconfined

    setup.sh now handles this automatically: during the Docker environment check it probes whether the daemon can load AppArmor policy, and if not, every generated compose service gets the security_opt entry and all helper docker run commands include --security-opt apparmor=unconfined.

    Warning: If you replace or hand-edit docker-compose.yaml on an affected host, make sure the security_opt entries survive — a compose file without them will deploy fine but fail on the next container recreate. Regenerating with the current setup.sh restores them automatically.

    Container Health Check Failing¶

    Symptoms: Container shows "unhealthy"

    Diagnosis: 

    # Check health status details
docker inspect --format='{{json .State.Health}}' <container_name> | jq

# Check what health check is doing
docker inspect --format='{{json .Config.Healthcheck}}' <container_name> | jq

    Solutions by Container:

    n8n: 

    # Check n8n can respond
docker exec n8n curl -s http://localhost:5678/healthz

# Check database connection
docker exec n8n curl -s http://localhost:5678/healthz/db

    PostgreSQL: 

    # Check PostgreSQL is ready
docker exec n8n_postgres pg_isready -U n8n

# Check PostgreSQL logs
docker logs n8n_postgres --tail 50

    Management: 

    # Check API responds
docker exec n8n_management curl -s http://localhost:8000/api/health

# Check database connection
docker exec n8n_management python -c "from core.database import engine; print(engine.url)"

    Network & Connectivity¶

    Can't Access n8n¶

    Symptoms: Browser shows timeout or connection refused

    Diagnosis: 

    # Test from server
curl -k https://localhost/healthz

# Test nginx
docker exec n8n_nginx nginx -t

# Check ports are listening
ss -tlpn | grep -E ':(80|443)'

    Solutions:

    1. Check nginx is running: 

      docker compose ps nginx
docker compose restart nginx

    2. Check firewall: 

      # UFW
sudo ufw status
sudo ufw allow 443/tcp

# firewalld
sudo firewall-cmd --list-ports
sudo firewall-cmd --add-port=443/tcp --permanent

    3. Check DNS resolution: 

      dig your-domain.com
nslookup your-domain.com

    Can't Access Management Console¶

    Symptoms: Management console doesn't respond

    Solutions:

    1. Check nginx is running: 

      docker ps | grep n8n_nginx

    2. Check management container is running: 

      docker ps | grep n8n_management

    3. Verify nginx config has management location block: 

      docker exec n8n_nginx cat /etc/nginx/nginx.conf | grep -A 10 "location /management"

    4. Restart nginx: 

      docker compose restart nginx

    502 Bad Gateway¶

    Symptoms: Nginx returns 502 error

    Cause: Backend service is down or unreachable

    Solutions:

    1. Check backend is running: 

      # For n8n
docker compose ps n8n
docker logs n8n --tail 50

# For management
docker compose ps n8n_management
docker logs n8n_management --tail 50

    2. Check backend is healthy: 

      # n8n
docker exec n8n curl -s http://localhost:5678/healthz

# Management
docker exec n8n_management curl -s http://localhost:8000/api/health

    3. Restart services: 

      docker compose restart n8n n8n_management nginx

    Database Issues¶

    PostgreSQL Won't Start¶

    Symptoms: postgres container exits or won't become healthy

    Diagnosis: 

    docker logs n8n_postgres --tail 100

    Solutions:

    1. Disk space: 

      df -h
# Clean up if needed
docker system prune -f

    2. Corrupted data: 

      # Warning: This will lose data if no backup
docker volume rm n8n_postgres_data
docker compose up -d postgres

    3. Permission issues: 

      docker exec n8n_postgres ls -la /var/lib/postgresql/data

    Can't Connect to Database¶

    Symptoms: "Connection refused" or authentication errors

    Diagnosis: 

    # Check PostgreSQL is ready
docker exec n8n_postgres pg_isready -U n8n

# Check from n8n container
docker exec n8n ping -c 1 n8n_postgres

# Test authentication
docker exec n8n_postgres psql -U n8n -d n8n -c "SELECT 1"

    Solutions:

    1. Check password in .env: 

      grep POSTGRES .env

    2. Check PostgreSQL is accepting connections: 

      docker exec n8n_postgres cat /var/lib/postgresql/data/pg_hba.conf

    3. Restart PostgreSQL: 

      docker compose restart postgres

    Database Full or Slow¶

    Symptoms: Slow queries, disk space errors

    Solutions:

    1. Check database size: 

      docker exec n8n_postgres psql -U n8n -c "
  SELECT pg_database.datname,
         pg_size_pretty(pg_database_size(pg_database.datname)) AS size
  FROM pg_database ORDER BY pg_database_size(pg_database.datname) DESC;
"

    2. Clean old executions: 

      docker exec n8n_postgres psql -U n8n -d n8n -c "
  DELETE FROM execution_entity WHERE finished_at < NOW() - INTERVAL '30 days';
"

    3. Vacuum database: 

      docker exec n8n_postgres psql -U n8n -d n8n -c "VACUUM FULL;"

    SSL Certificate Issues¶

    Certificate Expired or Invalid¶

    Symptoms: Browser shows certificate warning

    Diagnosis: 

    # Check certificate dates
docker exec n8n_nginx openssl x509 -in /etc/letsencrypt/live/your-domain.com/cert.pem -dates -noout

# Check from outside
echo | openssl s_client -connect your-domain.com:443 2>/dev/null | openssl x509 -noout -dates

    Solutions:

    1. Check certbot logs first — if they show Unable to find deploy-hook command docker in the PATH every 12 hours, renewals have been silently failing entirely. See Renewals Silently Failing in the Certbot guide: update docker-compose.yaml to the current version (its certbot entrypoint installs the Docker CLI at container start) and docker compose up -d --force-recreate certbot. 

      docker logs n8n_certbot --tail 100

    2. Force renewal (recommended — disables random sleep delay): 

      docker exec n8n_certbot certbot renew --force-renewal --no-random-sleep-on-renew
docker compose restart nginx

# Public Website installs: n8n_nginx_router terminates SSL on 443 —
# reload it too or the old certificate keeps being served
docker exec n8n_nginx_router nginx -s reload

    The --no-random-sleep-on-renew flag is important: by default certbot adds a random delay of up to 8 minutes before each renewal attempt, which causes the Management Console "Force Renewal" button to time out. The Management Console uses this flag automatically and waits up to 5 minutes for completion. The scheduled 12-hour renewal loop in docker-compose.yaml now uses it as well.

    1. Verify DNS credentials: 
      cat cloudflare.ini  # or your DNS provider file

    Force Renewal Times Out from Management Console¶

    Symptoms: Clicking "Force Renewal" in the Management Console returns a timeout error, but checking afterward shows the certificate was actually renewed.

    Cause: Certbot's default random sleep delay (up to 8 minutes) exceeded the previous web request timeout.

    Solution: This was fixed by adding --no-random-sleep-on-renew to the certbot command and increasing the frontend API timeout to 5 minutes. Pull the latest Management image:

    docker compose pull n8n_management
docker compose up -d n8n_management

    Certbot Missing DNS Plugin¶

    Symptoms: Renewal fails with The requested dns-cloudflare plugin does not appear to be installed.

    Cause: The certbot container is using the base certbot/certbot image instead of the DNS-provider variant.

    Solution: Check .env for the correct DNS image: 

    grep -i certbot .env
# Should show: DNS_CERTBOT_IMAGE=certbot/dns-cloudflare

    If missing or wrong, set it and recreate the container: 

    docker compose up -d --force-recreate certbot

    Certificate Not Found¶

    Symptoms: "Certificate not found" errors

    Solutions:

    1. Check certificate exists: 

      docker exec n8n_nginx ls -la /etc/letsencrypt/live/

    2. Check Let's Encrypt volume: 

      docker volume inspect letsencrypt

    3. Request new certificate: 

      docker exec n8n_certbot certbot certonly \
  --dns-cloudflare \
  --dns-cloudflare-credentials /etc/letsencrypt/cloudflare.ini \
  -d your-domain.com

    Backup Issues¶

    Backup Fails¶

    Symptoms: Backup shows "failed" status

    Diagnosis: 

    # Check management logs
docker logs n8n_management --tail 100 | grep -i backup

# Check disk space
df -h

    Solutions:

    1. PostgreSQL connection: 

      docker exec n8n_management pg_isready -h postgres -U n8n

    2. Disk space: 

      # Clean old backups
# Via UI or:
docker exec n8n_management rm /app/backups/old_backup.dump

    3. NFS issues: 

      docker exec n8n_management mount | grep nfs
docker exec n8n_management df -h /mnt/nfs

    NFS Mount Issues¶

    Symptoms: NFS shows disconnected

    Diagnosis: 

    # Test NFS server
showmount -e nfs-server-ip

# Test mount
docker exec n8n_management mount -t nfs nfs-server:/path /mnt/test

    Solutions:

    1. Check network: 

      docker exec n8n_management ping -c 1 nfs-server-ip
docker exec n8n_management nc -zv nfs-server-ip 2049

    2. Check exports on NFS server: 

      # On NFS server
cat /etc/exports
exportfs -v

    3. Remount: 

      docker compose restart n8n_management

    Authentication Issues¶

    Can't Log In to Management Console¶

    Symptoms: Login fails with valid credentials

    Solutions:

    1. Reset password via CLI: 

      docker exec n8n_management python -c "
from core.database import SessionLocal
from models.user import User
from core.security import get_password_hash

db = SessionLocal()
user = db.query(User).filter(User.username == 'admin').first()
user.hashed_password = get_password_hash('new-password-here')
db.commit()
print('Password updated')
"

    2. Check user exists: 

      docker exec n8n_postgres psql -U n8n -d n8n_management -c "SELECT username, email FROM users;"

    3. Clear sessions: 

      docker compose restart n8n_management

    Session Expires Too Quickly¶

    Solution: 

    # Adjust session timeout in settings
# Via UI: Settings → Security → Session Timeout
# Or via API:
curl -X PUT https://your-domain.com/management/api/settings \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"session_timeout_hours": 48}'

    Redis & Status Cache Issues¶

    Redis Container Won't Start¶

    Symptoms: n8n_redis container fails to start or keeps restarting

    Diagnosis: 

    docker logs n8n_redis --tail 50
docker inspect n8n_redis

    Solutions:

    1. Check port conflict: 

      # Redis uses port 6379
ss -tlpn | grep 6379

    2. Check volume permissions: 

      docker volume inspect redis_data

    3. Restart Redis: 

      docker compose restart redis

    n8n_status Container Keeps Restarting¶

    Symptoms: n8n_status container restarts continuously

    Diagnosis: 

    docker logs n8n_status --tail 50

    Common Causes & Solutions:

    1. Redis not accessible (most common): 

      # n8n_status uses network_mode: host, so Redis must expose port to localhost
# Check Redis port is exposed:
docker compose ps redis
# Should show: 127.0.0.1:6379->6379/tcp

# Test Redis connectivity:
redis-cli ping

    2. Docker socket not mounted: 

      # Check n8n_status can access Docker
docker exec n8n_status docker ps 2>/dev/null || echo "Docker socket not accessible"

    Slow Tab Loading Despite Redis¶

    Symptoms: Network/Health tabs still slow even with Redis running

    Diagnosis: 

    # Check if data is being cached
redis-cli KEYS "system:*"
redis-cli KEYS "containers:*"

# Check data freshness
redis-cli GET system:network | jq '.collected_at'

    Solutions:

    1. Verify n8n_status is collecting: 

      docker logs n8n_status --tail 20
# Should show "Collect X executed successfully"

    2. Check management console Redis connection: 

      curl -s https://your-domain.com/management/api/system/cache-status | jq

    3. Force refresh from UI:

    4. Click the refresh button on the affected tab
    5. This bypasses cache and triggers direct collection

    Cloudflare/Tailscale Showing as Down¶

    Symptoms: Cards show services as down when they're actually running

    Solutions:

    1. Rebuild n8n_status with latest code: 

      docker compose build n8n_status
docker compose up -d n8n_status

    2. Clear Redis cache: 

      redis-cli DEL system:cloudflare system:tailscale

    3. Check field name compatibility: The cached data must use field names: installed, running, logged_in (not available, is_running, connected)

    File Browser Issues¶

    File Browser Showing Login Prompt¶

    Symptoms: File Browser asks for username/password despite proxy auth

    Diagnosis: 

    # Check File Browser config
docker exec n8n_filebrowser cat /config/settings.json

    Solutions:

    1. Verify config file has proxy auth: 

      {
  "auth": {
    "method": "proxy",
    "header": "X-Remote-User"
  }
}

    2. Rebuild with correct config: 

      # Check .filebrowser.json exists with correct format
cat .filebrowser.json

# Restart File Browser
docker compose restart filebrowser

    File Browser 500 Error¶

    Symptoms: Accessing /files/ returns 500 Internal Server Error

    Cause: Usually the auth_request directive in nginx failing

    Solutions:

    1. Check nginx logs: 

      docker logs n8n_nginx --tail 50 | grep files

    2. Verify auth_request is commented out: 

      docker exec n8n_nginx cat /etc/nginx/nginx.conf | grep -A5 "location /files"
# Should show: #auth_request /management/api/auth/verify;

    3. Reload nginx config: 

      docker exec n8n_nginx nginx -s reload

    File Browser Assets Not Loading¶

    Symptoms: File Browser UI partially loads, CSS/JS missing

    Diagnosis: 

    # Check baseURL is set
docker exec n8n_filebrowser cat /config/settings.json | grep baseURL

    Solution: Ensure .filebrowser.json has "baseURL": "/files": 

    {
  "baseURL": "/files",
  ...
}

    File Browser iframe Too Small¶

    Symptoms: File Browser appears in a tiny frame in management console

    Solution: This was fixed in PR #322. Update to latest version: 

    git pull
docker compose build n8n_management
docker compose up -d n8n_management

    Performance Issues¶

    High CPU Usage¶

    Diagnosis: 

    docker stats
top

    Solutions:

    1. Identify culprit container: 

      docker stats --no-stream

    2. Check for runaway workflows:

    3. Open n8n UI
    4. Check Executions for stuck jobs

    5. Disable problematic workflows

    6. Limit container resources: 

      # In docker-compose.yaml
services:
  n8n:
    deploy:
      resources:
        limits:
          cpus: '2'

    High Memory Usage¶

    Diagnosis: 

    docker stats --no-stream --format "table {{.Name}}\t{{.MemUsage}}"
free -h

    Solutions:

    1. Increase swap: 

      sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

    2. Limit container memory: 

      services:
  n8n:
    deploy:
      resources:
        limits:
          memory: 2G

    3. Clean execution data: 

      # Via n8n settings or:
docker exec n8n_postgres psql -U n8n -d n8n -c "
  DELETE FROM execution_entity WHERE finished_at < NOW() - INTERVAL '7 days';
"

    Slow Workflows¶

    Solutions:

    1. Check database performance: 

      docker exec n8n_postgres psql -U n8n -d n8n -c "
  SELECT * FROM pg_stat_activity WHERE state = 'active';
"

    2. Add database indexes: 

      docker exec n8n_postgres psql -U n8n -d n8n -c "
  CREATE INDEX IF NOT EXISTS idx_execution_workflow ON execution_entity(workflow_id);
"

    3. Vacuum database: 

      docker exec n8n_postgres psql -U n8n -d n8n -c "VACUUM ANALYZE;"

    Logs & Debugging¶

    View All Logs¶

    # All services
docker compose logs -f

# Specific service
docker compose logs -f n8n
docker compose logs -f n8n_management
docker compose logs -f nginx

# Last N lines
docker compose logs --tail 100 n8n

    Enable Debug Logging¶

    n8n: 

    # Add to .env
N8N_LOG_LEVEL=debug

# Restart
docker compose restart n8n

    Management: 

    # Add to .env
DEBUG=true

# Restart
docker compose restart n8n_management

    Export Logs for Support¶

    # Create support bundle
mkdir -p support-bundle
docker compose logs > support-bundle/docker-logs.txt
docker compose ps > support-bundle/container-status.txt
./scripts/health_check.sh > support-bundle/health-check.txt 2>&1
df -h > support-bundle/disk-usage.txt
free -h > support-bundle/memory-usage.txt
docker stats --no-stream > support-bundle/container-stats.txt

# Create archive
tar -czf support-bundle.tar.gz support-bundle/

    Custom Nginx Configuration¶

    The nginx configuration for your deployment lives at ./nginx.conf in your project directory (generated by setup.sh, then yours to extend).

    Adding Custom Headers¶

    Add security headers in the server block:

    add_header X-Content-Type-Options nosniff;
add_header X-Frame-Options SAMEORIGIN;
add_header X-XSS-Protection "1; mode=block";
add_header Referrer-Policy strict-origin-when-cross-origin;
add_header Content-Security-Policy "default-src 'self'";

    Rate Limiting¶

    Add rate limiting to prevent abuse:

    # In http block
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;

# In location block
location /webhook/ {
    limit_req zone=api burst=20 nodelay;
    # ... rest of config
}

    Applying Changes¶

    After modifying nginx.conf:

    # Test configuration
docker exec n8n_nginx nginx -t

# Reload nginx
docker exec n8n_nginx nginx -s reload
